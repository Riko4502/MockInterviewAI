# Аудит архитектуры и ограничения онлайн-песочницы (Sandbox)

В данном документе зафиксирован технический аудит текущей реализации песочницы (`apps/web/src/features/sandbox`), выявленные архитектурные ограничения, риски и дорожная карта (roadmap) по их устранению.

---

## 1. Совместное редактирование (Concurrency & Realtime)

### 1.1. Стратегия Last-Write-Wins (LWW) вместо CRDT / OT
* **Текущее состояние:** Синхронизация кода в `useSandboxRealtime.ts` передаёт **полный текст файла** (`code-update`) при каждом изменении локального редактора.
* **Проблема:** При одновременном вводе двумя и более участниками (интервьюер и кандидат) более позднее сообщение перезаписывает весь буфер собеседника. Возникают гонки ввода, потеря набранных символов и мерцание курсора.
* **Решение:** Переход на **CRDT** (Conflict-free Replicated Data Types), например **Yjs** (`yjs`, `y-monaco`, `y-websocket`) или **Automerge**. Это обеспечит посимвольное слияние изменений без блокировок и конфликтов.

### 1.2. Смещение абсолютных позиций курсоров
* **Текущее состояние:** Позиция курсора передаётся абсолютными координатами `{ line, column }`.
* **Проблема:** Если первый участник вставит строку в начале файла, курсор второго участника в конце файла визуально останется на прежнем номере строки, указывая на неверный фрагмент кода.
* **Решение:** Привязка курсоров к относительным позициям документа через механизм awareness/presence в Yjs.

## 2. Выполнение и тестирование кода (Code Execution)

### 2.1. Отключённый запуск кода (Run Code)
* **Текущее состояние:** Кнопка «Run Code» в `SandboxHeaderActions.tsx` заблокирована (`disabled={true}`).
* **Проблема:** Пользователь не может запустить написанный алгоритм и проверить решение на тестах внутри песочницы.
* **Решение:** 
  1. Реализовать сквозной клиентский вызов к сервису `apps/code-runner` через API шлюз (`apps/api`).
  2. Поддержать стриминг `stdout`/`stderr` и результатов прогона тестов в консольную панель (`SandboxConsolePanel`).
  3. Обеспечить безопасность изоляции выполнения (Docker / gVisor / Firecracker / Isolate).

---

## 3. Медиа-связь и видеовиджет (WebRTC & LiveKit)

### 3.1. Ограничения резервного P2P Mesh режима
* **Текущее состояние:** Хук `useWebRTC.ts` реализует прямое P2P соединение 1:1.
* **Проблема:** Топология Full Mesh не масштабируется, если к собеседованию подключаются наблюдатели, HR или второй интервьюер (нагрузка на сеть растёт как $O(N^2)$).
* **Решение:** Использовать LiveKit SFU как основной режим для групповых комнат, а P2P оставить только в качестве fallback 1:1.

### 3.2. Синтетические медиапотоки
* **Текущее состояние:** При отсутствии камеры генерируется холст Canvas (20 FPS) и синтетический звук через `OscillatorNode`.
* **Проблема:** Нерациональный расход CPU/GPU на рендеринг искусственного видео/аудио, когда камера и микрофон выключены.
* **Решение:** Передавать статус активности медиа через сигналинг и LiveKit Track Mute/Unmute API, не создавая Canvas-потоки.

## 4. Модель данных и управление состоянием

### 4.1. Статический каталог задач
* **Текущее состояние:** Задачи захардкожены в статическом файле `tasks.ts` на клиенте.
* **Проблема:** Невозможно добавлять новые задачи без деплоя фронтенда; нет поддержки фильтрации, категорий, тегов и серверной валидации тестов.
* **Решение:** Загрузка каталога задач и тестовых наборов через NestJS REST API / TanStack Query с кэшированием.

### 4.2. Отсутствие истории изменений и таймлайна интервью (Code Playback)
* **Текущее состояние:** В Redis сохраняется только последнее состояние кода комнаты (`session:code:<id>`).
* **Проблема:** Интервьюер не может просмотреть историю правок кандидата после интервью и оценить динамику решения задачи.
* **Решение:** Логирование diff-снимков или Yjs update-векторов в S3 / PostgreSQL для последующего воспроизведения таймлайна (code playback).

---

## 5. AI-подсказки и ассистент

### 5.1. Статический список подсказок
* **Текущее состояние:** Подсказки берутся из предопределённого массива строк в конфигурации задачи.
* **Проблема:** Подсказки не учитывают фактический контекст и код кандидата (например, синтаксические ошибки или неоптимальную асимптотику).
* **Решение:** Интеграция LLM-ассистента с потоковым анализом текущего AST и контекстными наводящими вопросами.

## Сводная дорожная карта (Roadmap)

| Приоритет | Направление | Задача | Ожидаемый эффект |
| :--- | :--- | :--- | :--- |
| 🔴 **Высокий** | Коллаборация | Внедрение **Yjs + Monaco** | Исключение конфликтов и потери кода при параллельном вводе |
| 🔴 **Высокий** | Выполнение | Интеграция с `apps/code-runner` | Рабочий запуск кода и автотестов для всех поддерживаемых языков |
| 🟡 **Средний** | Задачи | Серверный каталог задач в `apps/api` | Динамическое добавление задач, скрытые тест-кейсы |
| 🟡 **Средний** | Аналитика | История версий (Code Playback) | Возможность ретроспективы и ревью процесса написания кода |
| 🟢 **Низкий** | AI | Контекстные подсказки через LLM | Адаптивная помощь кандидату во время решения |
