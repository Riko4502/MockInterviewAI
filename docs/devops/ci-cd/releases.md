# Релизы и Автоматизация версий

Процесс выпуска версий в проекте полностью автоматизирован и базируется на стандартах **SemVer** и Git-тегах.

> 📖 **Полная инструкция для разработчиков:**
> См. документ [**`docs/RELEASES.md`**](../../RELEASES.md).

---

## 1. Пайплайн релиза (`.github/workflows/release.yml`)

Workflow запускается автоматически при пуше тега `v*` (например, `git push origin v1.0.0`):

```text
┌─────────────────┐       ┌───────────────────────────────────────────────────────────┐
│ Git Tag: v1.0.0 │ ───►  │ GitHub Actions (release.yml)                              │
└─────────────────┘       │ 1. Сборка Web + API (TypeScript / Turborepo)              │
                          │ 2. Компиляция Go-бинарника (Linux amd64)                  │
                          │ 3. Упаковка в ZIP: mock-interview-ai-v1.0.0.zip           │
                          │ 4. Загрузка в S3 (s3://bucket/public/releases/)          │
                          │ 5. Отправка Telegram анонса со ссылкой на скачивание      │
                          └───────────────────────────────────────────────────────────┘
```

---

## 2. Автоматическое составление черновиков (Release Drafter)

Файл `.github/workflows/draft-release.yml` работает в фоновом режиме:
* При каждом мерже в `dev` или `main` он анализирует заголовки PR (Conventional Commits: `feat:`, `fix:`, `refactor:`, `chore:`).
* Автоматически обновляет черновик релиза на GitHub со структурированным списком изменений (Changelog) и автоматически рассчитывает следующий номер версии (SemVer).
