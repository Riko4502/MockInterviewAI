# Initiative 1. Доступ пользователей и управление профилем

Цель инициативы — дать пользователю возможность зарегистрироваться, войти в систему и управлять своим аккаунтом.

## Как читать блок State

`State` описывает состояния конкретного пользовательского сценария или UI: что сейчас происходит, что должен показать интерфейс и какие действия доступны пользователю. Это аналитическая модель — не каждое состояние обязано превращаться в отдельный `useState` или enum в коде. На практике часть состояний будет принадлежать React Hook Form/Zod, часть — TanStack Query, а часть определяется ответами Backend.

## Epic 1.1. Аутентификация

### Feature 1.1.1. Регистрация

**User Story**

> Как новый пользователь, я хочу зарегистрироваться в сервисе, чтобы получить доступ к интервью и другим возможностям платформы.

**Use Case**

```
1. Пользователь открывает страницу регистрации.
2. Вводит имя, email, пароль.
3. Система валидирует данные.
4. Пользователь отправляет форму.
5. Backend создаёт аккаунт.
6. Пользователь получает авторизованную сессию
   либо переходит на страницу входа.

```

**State**

- `idle` — форма открыта, регистрация ещё не начата.
- `filling` — пользователь заполняет поля формы.
- `submitting` — данные отправлены на Backend, ожидается ответ.
- `success` — аккаунт успешно создан.
- `validation_error` — данные формы не прошли валидацию.
- `email_already_exists` — пользователь с таким email уже зарегистрирован.
- `server_error` — регистрация не выполнена из-за ошибки сервера или сети.

**UI**

```
SignUpPage
└── SignUpForm
    ├── NameInput
    ├── EmailInput
    ├── PasswordInput
    ├── ConfirmPasswordInput
    ├── ValidationMessage
    └── SubmitButton

```

- `authenticated` — вход выполнен успешно, пользователь авторизован.
- `invalid_credentials` — Backend отклонил email/пароль как неверные.
- `server_error` — ошибка сервера или сети.

**User Story**

> Как авторизованный пользователь, я хочу выйти из аккаунта, чтобы завершить свою сессию.

**Use Case**

```

- `unauthenticated` — сессия успешно завершена, пользователь больше не авторизован.
- `error` — не удалось корректно завершить сессию из-за ошибки сервера или сети.

# Epic 3.1. Создание интервью

## Feature 3.1.1. Создание сессии

**User Story**

> Как пользователь, я хочу создать интервью-сессию, чтобы пригласить другого участника и провести интервью.

**Use Case**

```
1. Пользователь нажимает «Создать интервью».
2. Выбирает настройки.
3. Указывает язык программирования.

- `created` — сессия успешно создана, пользователь получает ссылку и переходит дальше.
- `validation_error` — параметры сессии не прошли валидацию.
- `server_error` — сессию не удалось создать из-за ошибки сервера или сети.

## Feature 3.1.2. Закрытая сессия

**User Story**

> Как создатель интервью, я хочу защитить сессию паролем, чтобы к ней могли подключиться только приглашённые пользователи.

**Use Case**

```
1. Создатель выбирает Private session.
2. Устанавливает пароль.
3. Другой пользователь открывает ссылку.
4. Система запрашивает пароль.
5. Пользователь вводит пароль.
6. Backend проверяет его.
7. При успехе пользователь получает доступ.

```

**State**

- `password_required` — сессия защищена, пользователь должен ввести пароль.
- `checking_password` — пароль отправлен на Backend и проверяется.
- `access_granted` — пароль корректный, доступ к сессии разрешён.
- `invalid_password` — пароль неверный; пользователь может попробовать снова.
- `session_unavailable` — сессия недоступна независимо от пароля: например, завершена или отменена.

# Epic 3.4. Жизненный цикл интервью

 завела явный lifecycle:

```
scheduled
    ↓
waiting
    ↓
active
    ↓
finished

```

Дополнительно:

```
cancelled

```

## Feature 3.4.1. Присоединение к интервью

**User Story**

> Как приглашённый участник, я хочу присоединиться к сессии, чтобы начать интервью.

**State**

- `connecting` — выполняется подключение к сессии и установка realtime-соединения.
- `waiting` — пользователь уже вошёл в сессию, но ожидает второго участника или начала интервью.
- `connected` — пользователь подключён к активной сессии.
- `reconnecting` — соединение временно потеряно, система пытается восстановить его автоматически.
- `disconnected` — соединение потеряно и автоматически восстановить его не удалось.
- `access_denied` — Backend запретил пользователю доступ к сессии.
- `session_finished` — интервью уже завершено, подключение к активной сессии невозможно.

**UI**

```
InterviewRoomPage

```

---

## Feature 3.4.2. Завершение интервью

**User Story**

> Как участник интервью, я хочу завершить интервью, чтобы перейти к сохранению результатов и обратной связи.

**Use Case**

```
1. Пользователь нажимает Finish.
2. Система запрашивает подтверждение.
3. Backend переводит session → finished.
4. Все участники получают realtime event.
5. Пользователи переходят на feedback page.

```

**State**

- `active` — интервью идёт, завершение ещё не инициировано.
- `finish_confirmation` — пользователь запросил завершение, UI ожидает подтверждения действия.
- `finishing` — запрос на завершение отправлен на Backend и обрабатывается.
- `finished` — Backend успешно завершил интервью; пользователи могут перейти к feedback.
- `error` — завершить интервью не удалось; UI сообщает об ошибке и позволяет повторить действие.

**UI**

```
FinishInterviewButton
FinishInterviewDialog

## Feature 4.2.2. Синхронизация кода

**User Story**

> Как участник интервью, я хочу видеть изменения второго участника в реальном времени, чтобы совместно работать с одним исходным кодом.

**Use Case**

```

↓

↓

↓

↓

```

**State**

- `synced` — локальная и удалённая версии документа синхронизированы.
- `syncing` — изменения отправляются или применяются между участниками.
- `offline` — realtime-соединение отсутствует; новые изменения временно не синхронизируются.
- `reconnecting` — система пытается восстановить realtime-соединение и синхронизацию.
- `conflict` — обнаружено конфликтующее состояние документа; при использовании CRDT это обычно внутреннее техническое состояние, а не отдельный UI-state.

# Epic 5.2. Поиск участников

## Feature 5.2.1. Поиск по стеку

**User Story**

> Как пользователь, я хочу искать участников по технологии, чтобы найти человека с нужным мне стеком.

**State**

- `idle` — поиск ещё не выполнялся или пользователь ещё не задал параметры.
- `loading` — выполняется загрузка результатов.

# Epic 5.3. Отклик на карточку

## Feature 5.3.1. Отправка отклика

**User Story**

> Как пользователь, я хочу откликнуться на карточку другого пользователя, чтобы предложить провести совместное интервью.

**Use Case**

```
1. Пользователь открывает карточку.
2. Нажимает Respond.
3. Backend создаёт response.
4. Владелец карточки получает уведомление.

```

**State**

- `available` — пользователь может отправить отклик на карточку.
- `sending` — отклик отправляется на Backend; повторная отправка блокируется.
- `sent` — отклик успешно создан.
- `already_sent` — пользователь уже отправлял отклик на эту карточку, повторный отклик недоступен.
- `error` — отклик не удалось отправить; UI сообщает об ошибке.

**UI**

```
RespondButton
ResponseSuccessMessage

```

## Feature 5.3.2. Принятие отклика

Владелец карточки должен иметь возможность принять или отклонить полученный отклик.

**User Story**

> Как автор карточки, я хочу принять отклик, чтобы сформировать пару и создать интервью.

**Use Case**

```
Response received
↓
Accept
↓
Match created
↓
InterviewSession created
↓
both users become participants

```

**State**

- `pending` — отклик ожидает решения владельца карточки.
- `accepted` — отклик принят; пользователи могут быть объединены в match.
- `rejected` — владелец карточки отклонил отклик.
- `expired` — отклик больше не актуален и не может быть принят, например после истечения срока или закрытия карточки.

**UI**

# Epic 7.1. Подсказки во время интервью

## Feature 7.1.1. Запрос подсказки

**User Story**

> Как кандидат, я хочу получить небольшую AI-подсказку, если застрял на задаче, чтобы продолжить решение без получения готового ответа.

**Use Case**

```
1. Пользователь нажимает AI Hint.
2. Система проверяет:
   session active?
   user participant?
   hintsUsed < 3?

4. AI генерирует подсказку.
5. Подсказка сохраняется.
6. hintsUsed увеличивается.
7. Socket event отправляется всем участникам.
8. Подсказка появляется в UI.

```

**State**

- `available` — пользователь может запросить AI-подсказку, лимит ещё не исчерпан.
- `generating` — запрос принят, AI генерирует подсказку.
- `generated` — подсказка успешно получена и отображена участникам.
- `limit_reached` — пользователь использовал все доступные подсказки в этой сессии.
- `error` — подсказку не удалось получить из-за ошибки сервиса или сети.

**UI**

```
AiHintPanel
├── HintButton
├── RemainingHints
