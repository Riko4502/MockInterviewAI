# Руководство по релизам и версионированию (Release Guide)

Данный документ описывает процесс создания релизов, систему версионирования (SemVer) и работу автоматического CI/CD пайплайна в проекте.

---

## 1. Схема версионирования (Semantic Versioning)

В проекте используется стандарт **SemVer** вида `vMAJOR.MINOR.PATCH`:

* **`PATCH`** (`v1.0.1`) — исправление ошибок (bug fixes), мелкие правки.
* **`MINOR`** (`v1.1.0`) — новая функциональность с обратной совместимостью (новые фичи, экраны, ручки API).
* **`MAJOR`** (`v2.0.0`) — мажорные изменения с нарушением обратной совместимости (breaking changes, смена архитектуры).

---

## 2. Как создать и выпустить релиз

Релизы собираются и публикуются автоматически при пуше **Git-тега**.

### Пошаговый процесс:

```bash
# 1. Переключитесь на актуальную ветку dev или main
git checkout main
git pull origin main

# 2. Создайте тег с версией
git tag v1.0.0

# 3. Отправьте тег в репозиторий на GitHub
git push origin v1.0.0
```

---

## 3. Что происходит в CI/CD пайплайне (`.github/workflows/release.yml`)

После пуша тега GitHub Actions запускает автоматический релизный пайплайн:

```
┌──────────────┐      ┌─────────────────────────────┐      ┌──────────────────────────┐
│  Git Tag     │ ───> │  GitHub Actions (Release)   │ ───> │  Telegram Announcement   │
│  (v1.0.0)    │      │  1. Turborepo build (Web/API)│     │  - Список изменений      │
└──────────────┘      │  2. Go build (Realtime)     │      │  - Ссылка на скачивание  │
                      │  3. Упаковка в ZIP          │      │  - Ссылка на GitHub      │
                      │  4. Загрузка в S3           │      └──────────────────────────┘
                      └─────────────────────────────┘
```

1. **Компиляция проектов**:
   - `apps/web` (Next.js) и `apps/api` (NestJS) компилируются через `pnpm build` (Turborepo).
   - `apps/realtime` компилируется в бинарный исполняемый файл `bin/mock-interview-realtime`.
2. **Упаковка сборки**:
   - Формируется zip-архив вида `mock-interview-ai-v1.0.0.zip`.
3. **Хранилище S3**:
   - Архив загружается в бакет `mock-interview-storage` в каталог `public/releases/`.
   - *Примечание:* Если секреты S3 не настроены в GitHub Secrets, шаг загрузки безопасно пропускается.
4. **Telegram-анонс**:
   - Бот отправляет уведомление в топик релизов с деталями релиза, ссылкой на GitHub и прямой ссылкой на скачивание архива сборки из S3.

---

## 4. Ручной запуск через GitHub Actions

Если требуется пересобрать релиз или выпустить его без пуша тега:
1. Перейдите во вкладку **Actions** в репозитории на GitHub.
2. Выберите workflow **«Релиз, сборка в S3 и Telegram-анонс»**.
3. Нажмите **Run workflow**, укажите название тега (например, `v1.0.0`), заголовок и описание изменений.
