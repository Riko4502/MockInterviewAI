# Обзор архитектуры Backend

## 1. Состав серверных сервисов монорепозитория

Серверная часть платформы построена по сервис-ориентированной архитектуре (Service-Oriented Monorepo) с разделением ответственности:

```text
monorepo/
├── apps/
│   ├── api/          # Основной бизнес REST API (NestJS 11, Express, Prisma 7, PostgreSQL)
│   ├── realtime/     # Высоконагруженный WebSocket / WebRTC сервис комнат (Go 1.24, LiveKit)
│   └── code-runner/  # Изолированная среда безопасного запуска кода пользователей (Sandbox)
│
└── packages/
    ├── dto/          # Общие DTO и Zod-схемы валидации (@packages/dto)
    └── types/        # Общие доменные TypeScript интерфейсы и типы (@packages/types)
```

---

## 2. Разделение ответственности сервисов

```
 ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
 │   apps/web      │       │  apps/realtime  │       │   apps/api      │
 │  (Next.js App)  │       │  (Go WebSocket) │       │   (NestJS API)  │
 └────────┬────────┘       └────────┬────────┘       └────────┬────────┘
          │                         │                         │
          │                         │ (Redis Pub/Sub)         │ (Prisma 7)
          ▼                         ▼                         ▼
 ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
 │   MinIO / S3    │       │  Redis Cache    │       │   PostgreSQL    │
 │ (Media Storage) │       │  (State & Sync) │       │ (Relational DB) │
 └─────────────────┘       └─────────────────┘       └─────────────────┘
```

| Сервис | Технологический стек | Основные задачи |
| :--- | :--- | :--- |
| **`apps/api`** | **NestJS 11**, TypeScript, Prisma 7, PostgreSQL | Регистрация, аутентификация (JWT, Argon2id), профили пользователей, сессии интервью, обратная связь, лидерборд, REST API. |
| **`apps/realtime`** | **Go 1.27**, WebSocket, Redis, LiveKit | Синхронизация кода в реальном времени, передача медиапотоков (аудио/видео), комнаты интервью, пинги активности. |
| **`apps/code-runner`** | Go / Docker Sandbox | Безопасное выполнение произвольного кода кандидатов в изолированных контейнерах с ограничениями по памяти/CPU. |

---

## 3. Направление зависимостей (Dependency Rules)

```text
apps/api ────────► @packages/dto
apps/api ────────► @packages/types
apps/web ────────► @packages/dto

(apps/realtime — независимый Go модуль, потребляет контракты API/Redis)
```

### 🚫 Архитектурные запреты:
1. **`apps/api` не зависит от фронтенд-пакетов** (`@packages/ui` и `apps/web`).
2. **`packages/*` не могут импортировать код из `apps/*`**.
3. **Бизнес-логика не дублируется между сервисами**: `apps/api` является единственным источником правды для данных пользователей и постоянных сущностей БД.
