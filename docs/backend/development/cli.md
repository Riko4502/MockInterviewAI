# CLI и Утилиты Управления (Backend & Monorepo)

В данном руководстве описаны основные CLI-команды для управления базой данных, генерации контрактов, сидирования администраторов и запуска инструментов разработки.

---

## 1. Назначение роли Администратора (`seed:admin`)

Для начальной инициализации платформы и назначения прав администратора в API предусмотрен CLI-скрипт `seed:admin`.

### Использование

Команда запускается через `pnpm` в фильтре `api`:

```bash
# 1. Повышение существующего пользователя до роли ADMIN:
pnpm --filter api seed:admin -- --email admin@mockinterview.tech

# 2. Создание нового администратора (если пользователя с таким email еще нет):
pnpm --filter api seed:admin -- --email newadmin@mockinterview.tech --password "SuperSecret123!"
```

### Параметры

| Флаг | Обязательный | Описание |
| :--- | :---: | :--- |
| `--email <email>` | **Да** | Email пользователя, которому назначается роль `ADMIN`. |
| `--password <password>` | Нет | Пароль нового пользователя (требуется, если пользователь с таким email еще не зарегистрирован в базе данных). Хэшируется с использованием `Argon2id`. |

### Что делает скрипт под капотом

1. **Инициализация системных ролей и прав**:
   - Автоматически проверяет наличие системных ролей `ADMIN` и `USER` в таблице `roles`. Если они отсутствуют — создает их с флагом `isSystem = true`.
   - Проверяет и при необходимости сидирует базовый набор прав (`users:read`, `users:manage`, `roles:manage`, `sessions:manage`, `analytics:read`) и привязывает их к роли `ADMIN`.
2. **Поиск или создание пользователя**:
   - Если пользователь с переданным `--email` уже существует в таблице `users` — скрипт обновляет его поле `roleId`, устанавливая связь с системной ролью `ADMIN`.
   - Если пользователь не найден и передан `--password` — создается новая учетная запись с подтвержденным email (`emailVerified = true`) и ролью `ADMIN`.
3. **Мгновенная инвалидация сессий (Revocation)**:
   - При смене роли существующего пользователя скрипт находит все активные сессии в Redis по префиксу `auth:session:*` и удаляет их. Это форсирует перелогин и мгновенный выпуск нового JWT access-токена с правами `ADMIN` (защита от устаревших claims в JWT).

## 2. База данных и Prisma CLI

Все команды работы со схемой и миграциями PostgreSQL выполняются через Prisma CLI:

```bash
# Применение миграций разработки (создает новую миграцию при изменении schema.prisma)
pnpm run db:migrate
# или напрямую:
pnpm --filter api db:migrate:dev

# Применение уже созданных миграций (для staging/production/CI)
pnpm run db:migrate:deploy
# или напрямую:
pnpm --filter api db:migrate:deploy

# Перегенерация Prisma Client после изменения моделей
pnpm run db:generate
# или напрямую:
pnpm --filter api db:generate

# Открытие интерактивного веб-интерфейса Prisma Studio для просмотра БД
pnpm --filter api db:studio
```

## 3. Генерация контрактов и OpenAPI (`codegen`)

Для поддержания сквозной типобезопасности между NestJS и фронтенд-приложениями используется пайплайн кодогенерации:

```bash
# 1. Генерация OpenAPI v3 спецификации из NestJS контроллеров (без запуска Docker)
pnpm run generate:api
# или: pnpm --filter api generate:openapi

# 2. Генерация типизированного клиента Orval и React Query хуков в packages/api
pnpm run generate:client

# 3. Полный цикл (OpenAPI + Orval) одной командой:
pnpm run codegen

# 4. Проверка чистоты и актуальности сгенерированного кода (используется в CI)
pnpm run codegen:check
```

---

## 4. Управление локальной инфраструктурой (Docker)

Запуск зависимостей (PostgreSQL, Redis, RabbitMQ, MinIO S3):

```bash
# Поднять контейнеры в фоновом режиме
pnpm run infra:up

# Остановить контейнеры
pnpm run infra:down
```

## 5. Запуск тестов и линтеров

```bash
# Запуск юнит-тестов API (NestJS + Jest)
pnpm test:api
# или: pnpm --filter api test

# Запуск E2E тестов API (на реальных тестовых PG + Redis)
pnpm --filter api test:e2e

# Запуск конкретного E2E тест-сьюта:
pnpm --filter api test:e2e test/rbac.e2e-spec.ts

# Проверка качества кода линтером Biome
pnpm lint
# Автоисправление ошибок форматирования и линтинга
pnpm lint:fix
```

## 6. Эмуляция и тестирование SSE-уведомлений (`sse:send`)

Для тестирования реального времени, всплывающих уведомлений, инвайтов и бейджей без необходимости совершать действия в API:

```bash
# 1. Персональное уведомление:
pnpm sse:send --user dev-user-1 --title "Инвайт" --message "Вас ждут на интервью"

# 2. Быстрый пресет приглашения на интервью:
pnpm sse:send --user dev-user-1 --interview

# 3. Обновление счетчика непрочитанных:
pnpm sse:send --user dev-user-1 --badge 5

# 4. Общесистемный бродкаст:
pnpm sse:broadcast --message "Технические работы через 10 минут"

# 5. Интерактивный пошаговый мастер:
pnpm sse:send -i
```

*Подробное руководство со всеми флагами, пресетами и форматами данных: [sse-notifications-cli.md](./sse-notifications-cli.md).*
