# Frontend Testing

## Назначение

Для unit/component тестирования frontend **MockInterviewAI**
используются:

-   Vitest;
-   React Testing Library;
-   `@testing-library/jest-dom`;
-   `@testing-library/user-event`;
-   jsdom.

------------------------------------------------------------------------

## Принцип

Тесты должны проверять наблюдаемое пользователем поведение, а не
внутреннее устройство компонента.

------------------------------------------------------------------------

## Что тестировать

-   отображение важных UI-состояний;
-   пользовательские действия;
-   validation;
-   реакции интерфейса на успешные и ошибочные сценарии;
-   переиспользуемую логику, где тест снижает риск регрессии.

------------------------------------------------------------------------

## Чего избегать

-   тестов implementation details;
-   проверки внутренних переменных компонента;
-   бессмысленных snapshot-тестов без конкретной цели;
-   дублирования одной и той же проверки на нескольких уровнях.

------------------------------------------------------------------------

## Пользовательские действия

Для взаимодействия пользователя предпочтительно использовать
`@testing-library/user-event`.

Компонент следует находить по доступным пользователю признакам: role,
label, text и другим семантическим селекторам.

------------------------------------------------------------------------

## Ограничения и правила

-   Тест должен быть понятен по сценарию без чтения реализации
    компонента.
-   Не привязывать тест к Tailwind-классам, если класс не является
    частью проверяемого поведения.
-   Mock использовать только там, где необходимо изолировать внешнюю
    зависимость.
-   Ошибка теста должна помогать понять, какое пользовательское
    поведение сломано.
