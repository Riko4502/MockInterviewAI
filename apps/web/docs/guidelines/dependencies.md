# Frontend Dependencies

## Назначение

Документ фиксирует правила добавления сторонних frontend-библиотек в
**MockInterviewAI**.

------------------------------------------------------------------------

## Основной принцип

Новая dependency добавляется только тогда, когда она решает конкретную
задачу и её использование оправдано по сравнению с существующими
возможностями проекта.

Зависимость должна принадлежать workspace, который непосредственно её
использует.

Для frontend это обычно:

``` text
apps/web/package.json
```

------------------------------------------------------------------------

## Перед добавлением библиотеки

Необходимо проверить:

-   нет ли уже библиотеки с той же ответственностью;
-   нельзя ли решить задачу средствами текущего стека;
-   не создаёт ли библиотека конфликт существующих архитектурных
    решений;
-   является ли зависимость runtime или dev dependency;
-   требуется ли зафиксировать проектные conventions.

------------------------------------------------------------------------

## Guideline для библиотеки

Отдельный файл в `docs/guidelines/` создаётся не для каждого npm
package.

Guideline нужен, если у библиотеки есть:

-   собственные правила использования в проекте;
-   архитектурная ответственность;
-   ограничения;
-   договорённости о том, когда её использовать и когда не использовать.

Не нужно пересказывать официальную документацию библиотеки.

------------------------------------------------------------------------

## Примеры

Guideline оправдан для:

``` text
TanStack Query
Zustand
React Hook Form + Zod
Socket.IO Client
shadcn/ui
clsx
```

Пакеты, которые являются техническими зависимостями и не требуют
проектных conventions, отдельного guideline могут не иметь.

------------------------------------------------------------------------

## Архитектурное решение

Если новая библиотека:

-   заменяет существующий инфраструктурный инструмент;
-   влияет на архитектуру приложения;
-   создаёт новый системный подход;
-   меняет правила разработки,

решение должно быть дополнительно зафиксировано в `DECISIONS.md` или
отдельном ADR.
